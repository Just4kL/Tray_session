# Ветки: стабильная и бета

В репозитории две рабочие ветки. Названия исторические — застарели, когда
ветка была единственной; менять их смысла нет, важно помнить назначение.

| Ветка | Назначение | Кто ставит |
|---|---|---|
| `Tray-session` | **стабильная**. Ветка по умолчанию на GitHub. Сюда попадает проверенное. | все, включая автообновление |
| `app-Tray_session` | **бета**. Здесь живут новые функции и эксперименты. | вручную, осознанно |

## Правило

1. Новая функция или эксперимент — в `app-Tray_session`.
2. Ветка стабильная не трогается, пока функция не проверена в бета.
3. Когда функция проверена, изменения переносятся в `Tray-session`.
4. Релиз на GitHub собирается **только** из `Tray-session`:
   ```
   gh release create v0.7.29 TraySession.exe Tray_session_setup.exe \
     --repo Just4kL/Tray_session --target Tray-session --latest
   ```
5. После релиза пересобирается манифест — он попадает в репозиторий
   вместе со сборками:
   ```
   powershell -ExecutionPolicy Bypass -File tools\make-manifest.ps1
   ```

## Известное ограничение: автообновление не различает каналы

Константа `BRANCH` в `src/update.rs` жёстко указывает на `Tray-session`.
Поэтому бета-сборка, поставленная из `app-Tray_session`, при автопроверке
смотрит манифест стабильной ветки, видит, что файлы отличаются, и
**тихо ставит стабильную сборку** — то есть бета «откатывается» на стабиль.

Пока это так, на бету нужно:

- либо выключить автопроверку в «Параметрах → Обновления»;
- либо ставить бету вручную и не запускать проверку.

Когда каналов станет два по-настоящему, правится `BRANCH` (или вводится
чтение канала из конфига и отдельный `update_manifest.json` в бета-ветке).

## Оговорка про бэкапы

Бекапы 7-Zip (`.7z`) в репозиторий не попадают — это десятки мегабайт
на каждый билд. Взведённые туда файлы остаются локально.
