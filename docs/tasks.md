### C13 — Апдейтер зависает, exe пропадает, программа не перезапускается
**Статус:** [ ] открыт
**Создано:** 2026-10-01
**Обновлено:** 2026-10-01
**Приоритет:** CRITICAL
**Файлы:** src/update.rs (spawn_updater, run_updater, apply_update)
**Описание:**
При нажатии «Установить сейчас» в UI:
- окно программы зависает
- TraySession.exe пропадает
- появляется снова
- программа НЕ перезапускается
- в диспетчере задач висят ДВА процесса _updater_running.exe (оба ~1% CPU)
- окно Tray Session остаётся чёрным, не восстановилось
**Что воспроизведено:** пользователь видит, скриншоты сделаны.
**Последствия:** пользователь может остаться без рабочей программы после
нажатия «Установить сейчас». Блокирует любые живые тесты обновления.
**Что осталось:**
1. Разведка run_updater: последовательность rename → replace → spawn.
2. Понять, где обрывается цепочка.
3. Добавить fallback: если replace завершился, но spawn упал — восстановить
   старый exe из aside (rename обратно).
4. Логи в update_tmp/ для диагностики при следующем сбое.

### C14 — Апдейтер запускается многократно
**Статус:** [ ] открыт
**Создано:** 2026-10-01
**Приоритет:** HIGH (перенести в CRITICAL, если подтвердится)
**Файлы:** src/update.rs (spawn_updater)
**Описание:**
На скриншоте диспетчера задач — ДВА процесса _updater_running.exe

2. Если нет — добавить mutex на апдейтер (аналогично C5, но другое имя).
3. НЕ путать с C5 — тот защищает main window, этот — сам updater.

### C15 — Нет защиты от «обновления на ту же версию»
**Статус:** [ ] открыт
**Создано:** 2026-10-01
**Приоритет:** MEDIUM
**Файлы:** src/update.rs (plan_update), src/app.rs (блок обновлений)
**Описание:**
Если в манифесте beta-канала лежит та же версия, что установлена
(например, 0.7.33-beta.1 == текущая), апдейтер всё равно предлагает
обновление, потому что сравнение идёт по sha256 (AU-2), а не по version.
Пользователь случайно может запустить ненужное обновление и попасть
в C13.
**Что сделать:**
1. Сравнивать версию из манифеста с текущей VERSION.
2. Если версия == текущей И tag/version совпадают — не предлагать.
3. Если хеши отличаются, но версия та же — предупреждать: «файлы
   отличаются, но версия та же. Обновить?»
**Связано:** AU-2 (нет сравнения версий).

## AUTO-UPD — зафиксированная модель авто-обновления

**Каналы:**
- stable → ветка Tray-session
- beta → ветка app-Tray_session (**origin/beta кодом НЕ читается**)

**Манифест:** update_manifest.json в корне ветки канала. Поля: version,
build (YYYYMMDD), files[{name, sha256}]. Генерируется tools/make-manifest.ps1.

**Выбор канала:** ComboBox в «Параметры → Обновления», сохраняется в
config.json (update_channel). Апдейтер получает канал третьим CLI-аргументом.

**Публикация:** git commit в ветку канала — новый TraySession.exe +
installer + перегенерированный update_manifest.json. gh Releases кодом
не используется (только для людей).

## Правила гигиены

- **Тег после коммита, не до.** Порядок: commit → status пусто → tag → push
  ветки → push тега. Инцидент 2026-10-01: тег дважды ушёл на устаревший хеш.
- **Amend только до пуша.** Если коммит уже запушен или тегирован — не
  амендить, обновления идут следующим коммитом.
- **Скоуп фиксируется явно** — что трогать и что НЕ трогать.
- **Тесты не править под код** — код править под тесты.
