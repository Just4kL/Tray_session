### C15 — Перезапуск после успешной замены не срабатывает
**Статус:** [ ] открыт
**Создано:** 2026-10-01
**Приоритет:** CRITICAL
**Файлы:** src/update.rs (run_updater_inner, шаг 6), src/app.rs
(start_update_install, update), src/main.rs (C5 mutex)
**Описание (живой тест beta.2 → beta.3, 2026-10-01):**
update_report.json ok=true, updated=[TraySession.exe], юзерские файлы
сохранены, exe заменён (sha256 0215776A = beta.3), lock удалён. НО:
старый процесс остался жив, окно висело чёрным, новый процесс
не запустился. Ручной запуск показывает About v0.7.33-beta.3.
**Причина (разведка, без правок):**
1. `start_update_install` (app.rs:1408) только ставит quit_requested=true —
   процесс НЕ выходит (обещание «программа закроется» в комментарии
   не выполнено кодом). Успешный путь quit_requested никто не сбрасывает
   и exit не вызывает (app.rs:2866 — только откат при !ok).
2. Updater спавнит новый процесс ДО записи отчёта (update.rs:1224 раньше
   1240), без ожидания смерти старого; явного kill нет (нет
   TerminateProcess/OpenProcess — только wait_for_exit по файлу-флагу).
3. Новый процесс упирается в C5-mutex старого (main.rs:407-419):
   FindWindowW находит чёрное окно → ShowWindow → exit(0).
**Что осталось:** выбрать и реализовать вариант B (см. bugs.md, C15):
самовыход главного процесса по ok=true + ожидание смерти перед spawn.
**Связано:** C13a, C13b, C13c, C5.

### C16 — Нет защиты от «обновления на ту же версию»
(бывший C15, переименован 2026-10-01 — ID C15 отдан багу перезапуска)
**Статус:** [ ] открыт
**Создано:** 2026-10-01
**Приоритет:** MEDIUM
**Файлы:** src/update.rs (plan_update), src/app.rs (блок обновлений)
**Описание:**
Если в манифесте beta-канала лежит та же версия, что установлена
(например, 0.7.33-beta.1 == текущая), апдейтер всё равно предлагает
обновление, потому что сравнение идёт по sha256 (AU-2), а не по version.
Пользователь случайно может запустить ненужное обновление и попасть
в C13a/C13b.
**Что сделать:**
1. Сравнивать версию из манифеста с текущей VERSION.
2. Если версия == текущей И tag/version совпадают — не предлагать.
3. Если хеши отличаются, но версия та же — предупреждать: «файлы
   отличаются, но версия та же. Обновить?»
**Связано:** AU-2 (нет сравнения версий).

## AUTO-UPD — зафиксированная модель авто-обновления

**Каналы:**
- stable → ветка Tray-session
- beta → ветка app-Tray_session (**origin/beta кодом НЕ читается**)

**Манифест:** update_manifest.json в корне ветки канала. Поля: version,
build (YYYYMMDD), files[{name, sha256}]. Генерируется tools/make-manifest.ps1.

**Выбор канала:** ComboBox в «Параметры → Обновления», сохраняется в
config.json (update_channel). Апдейтер получает канал третьим CLI-аргументом.

**Публикация:** git commit в ветку канала — новый TraySession.exe +
installer + перегенерированный update_manifest.json. gh Releases кодом
не используется (только для людей).
